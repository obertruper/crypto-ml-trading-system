# ПОЛНОЕ ИСПРАВЛЕНИЕ ПРОБЛЕМЫ КОЛЛАПСА МОДЕЛИ

## Найденные и исправленные критические проблемы

### 1. Temperature Scaling (КРИТИЧЕСКАЯ ПРОБЛЕМА №1)
**Было:**
- `temperature_scaling: true`
- `temperature: 5.0`

**Проблема:** Temperature=5.0 делает все вероятности почти равными (softmax сглаживается), что разрушает градиенты и не даёт модели учиться различать классы.

**Исправлено:**
- `temperature_scaling: false`
- `temperature: 1.0`

### 2. Веса классов для FLAT (КРИТИЧЕСКАЯ ПРОБЛЕМА №2)
**Было:**
```yaml
class_weights:
- 5.0  # LONG
- 5.0  # SHORT
- 0.2  # FLAT - почти полностью игнорируется!
```

**Проблема:** Вес 0.2 для FLAT означает, что модель почти не получает градиентов за предсказание FLAT класса. При том что FLAT должен быть ~60% данных!

**Исправлено:**
```yaml
class_weights:
- 1.0  # LONG
- 1.0  # SHORT
- 1.0  # FLAT - равный вес для всех классов
```

### 3. Focal Loss параметры
**Было:**
- `use_focal_loss: true`
- `focal_gamma: 5.0` (слишком высокое)
- `focal_alpha: 0.7`

**Проблема:** Focal loss с gamma=5.0 слишком сильно усиливает уверенные предсказания и подавляет неуверенные, что приводит к коллапсу.

**Исправлено:**
- `use_focal_loss: false` (отключено полностью)
- `focal_gamma: 2.0`
- `focal_alpha: 0.25`

### 4. Wrong Direction Penalty
**Было:** `wrong_direction_penalty: 5.0`

**Проблема:** Слишком сильное наказание за неправильное направление заставляет модель "играть безопасно" и предсказывать только один класс.

**Исправлено:** `wrong_direction_penalty: 2.0`

### 5. Инициализация Direction Head
**Было:**
```yaml
direction_head_init:
  bias_init: anti_collapse
  weight_scale: 3.0
  add_noise: true
```

**Проблема:**
- anti_collapse bias может создавать искусственный дисбаланс
- weight_scale=3.0 создаёт слишком большие начальные веса

**Исправлено:**
```yaml
direction_head_init:
  bias_init: zeros
  weight_scale: 1.0
  add_noise: false
```

### 6. Entropy Regularization
**Было:**
- `entropy_regularization: 2.0`
- `min_entropy_weight: 1.0`
- `entropy_min_weight: 0.8`

**Проблема:** Слишком сильная регуляризация энтропии может мешать модели сходиться к оптимальному решению.

**Исправлено:**
- `entropy_regularization: 0.1`
- `min_entropy_weight: 0.1`
- `entropy_min_weight: 0.1`

### 7. Anti-Collapse Strength
**Было:** `anti_collapse_strength: 2.0`

**Исправлено:** `anti_collapse_strength: 0.5`

## Удалённые проблемные компоненты

1. **StagedTrainer** - вызывал model.eval() во время обучения
2. **CurriculumTrainer** - имел confidence thresholds
3. **staged_training конфигурация** - полностью удалена из config.yaml
4. **confidence_threshold логика** - удалена из модели

## Ожидаемые результаты после исправлений

После применения всех исправлений модель должна:
1. Предсказывать все 3 класса (LONG ~20%, SHORT ~20%, FLAT ~60%)
2. Иметь энтропию > 0.5 (идеально 0.8-1.0)
3. Не коллапсировать в один класс
4. Показывать стабильное обучение с постепенным улучшением метрик

## Команда для запуска

```bash
# Остановить все старые процессы
pkill -f "python.*train"

# Удалить старые чекпоинты
rm -f models_saved/*.pth

# Запустить с чистой конфигурацией
python main.py --mode train 2>&1 | tee training_fixed.log
```

## Мониторинг

Следите за этими метриками:
- **Энтропия направлений** - должна быть > 0.5
- **Распределение классов** - FLAT должен быть 50-70%
- **F1 Score** - должен расти постепенно
- **Win Rate** - должен быть стабильным

Если модель снова начнёт коллапсировать, проверьте:
1. Не запущены ли параллельные процессы обучения
2. Используется ли правильный config.yaml
3. Нет ли старых чекпоинтов в models_saved/
